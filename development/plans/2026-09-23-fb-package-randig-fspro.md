# FB Package Randig/FSPro Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `Randig` and `FSPro` selectable end-to-end through `runApp()`/`appTest()`, alongside the existing `FlamMap`/`MTT`/`TOM`/`Farsite` support, using the vendor's new `runrandig.exe`/`runfspro.exe` executables.

**Architecture:** `Randig` and `FSPro` do **not** use the "one command file listing many runs" model that `FlamMap`/`MTT`/`TOM`/`Farsite` use — each is invoked with positional CLI arguments directly (confirmed by running each exe with no arguments and reading its usage banner). `runApp()` is generalized to accept either a command-file path (`str`, existing apps) or a list of positional arguments (`list[str]`, Randig/FSPro), dispatching the `subprocess.Popen` argument list accordingly. `appTest()` gets a second dispatch branch for apps that use positional args instead of a command file. `genInputFile()` is **not** extended to build Randig/FSPro input files in this plan — their switch vocabularies are unrelated to the FlamMap-family switches `genInputFile()` already knows, and FSPro's own sample input file (`FSProInputs.txt`) is generated by a Java tool with a `[B@...` toString artifact literally baked into its own header comment, i.e. this is not a stable hand-authorable format. Callers who need a Randig/FSPro input file must supply their own file path for now.

**Tech Stack:** Python 3.12 (conda env `ProcessGeospatial`), pytest 9.x, stdlib `unittest.mock`.

**Spec:** Builds on `development/plans/2026-09-23-fb-package-core-integration.md`, which must land first (this plan modifies the same functions that plan already touched: `app_name_dict`, `app_exe_dict`, `runApp()`, `appTest()`). The CLI argument shapes below were captured empirically by running `runrandig.exe` and `runfspro.exe` with no arguments in the extracted `FireBehaviorModels.zip` package and reading their usage banners.

## Global Constraints

- `runrandig.exe` usage (confirmed via its own usage banner): `runrandig [LCPName] [InputsFileName] [outputBaseName] [FireListFile(optional, 0)] [WindSpeedGrid(optional, 0)] [WindDirGrid(optional, 0)]` — minimum 3 required positional args, up to 6.
- `runfspro.exe` usage (confirmed via its own usage banner): `runfspro [LCPName] [InputsFileName] [outputFileName] [ignitionFileName(optional, 0)] [barrierFileName(optional, 0)]` — minimum 3 required positional args, up to 5. Confirmed against the vendor's own sample invocation (`sampledata/FSPro/testFSPro.bat`), which passes all 5.
- Neither app reads a "command file" the way `runflammap.exe -> command_file.txt` works — the LCP/inputs/output/ignition paths go directly on the command line.
- New vendor sample data for these two apps lives at `FB/sampledata/Randig/` (`RandigInputs.txt`, `out/`) and `FB/sampledata/FSPro/` (`FSProInputs.txt`, `out/`), plus a **shared** landscape/ignition pair at `FB/sampledata/BlueMountain/` (`BlueMountain.tif`, `centerIgnit.shp`) referenced by both — this is a different sharing pattern than `FlamMap`/`MTT`/`Farsite`, whose sample LCP/ignition files live inside each app's own sample folder.
- This plan assumes Plan 1 (`2026-09-23-fb-package-core-integration.md`) is already applied: `app_name_dict`/`app_exe_dict` currently contain only `FlamMap`/`MTT`/`TOM`/`Farsite`, `runApp()` already has the `_buildAppEnv()` isolation from Plan 1's Task 5, and `tests/test_flammap_cli.py` already exists with Plan 1's tests passing.
- `runApp()`'s existing parameter name `command_file_path` is kept as-is for backward compatibility with any existing callers (e.g. `tests/farsite_testing.py`, `tests/mtt_testing.py` call it by that keyword) — it now accepts either a `str` (command-file path, existing behavior) or a `list[str]`/`tuple[str, ...]` (positional CLI args, new behavior for Randig/FSPro). This is a widening of the accepted type, not a rename.
- The new `cwd` parameter **must be appended after `suppress_messages`**, i.e. at the very end of `runApp()`'s parameter list (`app_select, command_file_path, app_exe_path=None, suppress_messages=False, cwd=None`), not inserted before it. `runApp()`'s current signature is `(app_select, command_file_path, app_exe_path=None, suppress_messages=False)` — any existing caller invoking it positionally (e.g. `runApp('FlamMap', path, None, True)`, intending `suppress_messages=True`) would silently have `True` bound to a `cwd` parameter inserted in the third/fourth slot instead. Appending `cwd` last keeps every existing positional call working unchanged.
- Out of scope: generating Randig/FSPro `.input` files via `genInputFile()`. Out of scope: wiring these into `tests/farsite_testing.py`-style example driver scripts (no such example exists for these two apps; add one only if requested separately).

```python
def runApp(app_select: str,
           command_file_path: Union[str, list, tuple],
           app_exe_path: Optional[str] = None,
           suppress_messages: bool = False,
           cwd: Optional[str] = None) -> tuple[str, str]:
    """
    Function to run the selected fire app through the command line interface
    :param app_select: The name of the selected fire modelling application.
        Options are "FlamMap", "MTT", "TOM", "Farsite", "Randig", "FSPro"
    :param command_file_path: Either the path to a command file (FlamMap, MTT,
        TOM, Farsite - each run's positional args are one line in this file),
        or a list/tuple of positional CLI arguments passed directly on the
        command line (Randig, FSPro - these apps have no command-file concept).
    :param app_exe_path: path to the app executable file
    :param suppress_messages: suppress intermediate print statements during program execution
    :param cwd: working directory to run the app in. If not given: for a
        command-file string, defaults to that file's directory (existing
        behavior); for a positional-args list, defaults to the current
        working directory. Appended as the LAST parameter (after
        suppress_messages, not before it) so any existing positional call
        using the old 4-parameter shape keeps working unchanged.
    :return: A tuple containing the standard output messages, and the CLI app errors
    """
    # Check if the FB folder exists within the supplementary_data folder
    # If not, download the application data
    if not os.path.exists(fb_path):
        downloadApps()

    if app_exe_path is None:
        # Get the name of the application executable file
        app_exe_path = app_exe_dict.get(app_select, None)

    if app_exe_path is not None:
        if not suppress_messages:
            print(f'\n<<<<< [flammap_cli.py] Running {app_select} >>>>>')

        if isinstance(command_file_path, (list, tuple)):
            popen_args = [app_exe_path] + [str(arg) for arg in command_file_path]
            run_cwd = cwd if cwd is not None else os.getcwd()
        else:
            popen_args = [app_exe_path, command_file_path]
            run_cwd = cwd if cwd is not None else os.path.dirname(command_file_path)

        # Run fire model through command line interface
        if not suppress_messages:
            print('Running CLI command...')
        app_cli = subprocess.Popen(
            popen_args,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            text=True,
            cwd=run_cwd,
            env=_buildAppEnv()
        )
        stdout, stderr = app_cli.communicate()
        if not suppress_messages:
            print(f'{stdout}\n{stderr}')

        del app_cli

        # Delete the current CLI app process if it's still running
        try:
            worker_proc = psutil.Process(os.getpid())
            for child in worker_proc.children(recursive=True):  # Kill all child processes running app
                if app_name_dict[app_select] in child.name():
                    child.kill()
        except psutil.NoSuchProcess:
            pass

        if not suppress_messages:
            print(f'<<<<< {app_select} modelling complete >>>>>')
    else:
        # Raise a value error
        raise ValueError(f'Invalid fire model selected.\n'
                         f'The "app_selection" variable be one of the following:\n'
                         f'{", ".join(app_name_dict.keys())}')

    return stdout, stderr
```

```python
def appTest(app_selection: str) -> None:
    """
    Function to run the Missoula Fire Lab Command Line Application test datasets
    :param app_selection: The name of the selected fire modelling application.
        Options are "FlamMap", "MTT", "TOM", "Farsite", "Randig", "FSPro".
        Default = "FlamMap".
    :return: None
    """
    app_testData_dict = {
        'FlamMap': os.path.join(fb_path, 'sampledata', 'FlamMap'),
        'MTT': os.path.join(fb_path, 'sampledata', 'MTT'),
        'TOM': os.path.join(fb_path, 'sampledata', 'MTT'),
        'Farsite': os.path.join(fb_path, 'sampledata', 'Farsite'),
    }

    # Randig and FSPro take positional CLI args, not a command file. Both
    # sample datasets share their landscape/ignition files out of the
    # sibling BlueMountain sample folder rather than owning their own copy.
    blue_mountain_dir = os.path.join(fb_path, 'sampledata', 'BlueMountain')
    app_directArgs_dict = {
        'Randig': [
            os.path.join(blue_mountain_dir, 'BlueMountain.tif'),
            os.path.join(fb_path, 'sampledata', 'Randig', 'RandigInputs.txt'),
            os.path.join(fb_path, 'sampledata', 'Randig', 'out', 'test'),
        ],
        'FSPro': [
            os.path.join(blue_mountain_dir, 'BlueMountain.tif'),
            os.path.join(fb_path, 'sampledata', 'FSPro', 'FSProInputs.txt'),
            os.path.join(fb_path, 'sampledata', 'FSPro', 'out', 'test'),
            os.path.join(blue_mountain_dir, 'centerIgnit.shp'),
            '0',
        ],
    }

    if app_selection in app_directArgs_dict:
        runApp(app_selection, app_directArgs_dict[app_selection])
        return

    # Get the test application path
    test_data_path = app_testData_dict.get(app_selection, None)

    if test_data_path is not None:
        # Vendor sample data names the command file inconsistently per app:
        # "...Command.txt" for FlamMap/MTT, "...Cmd.txt" for Farsite.
        command_file_matches = (
            glob.glob(os.path.join(test_data_path, '*Command.txt'))
            or glob.glob(os.path.join(test_data_path, '*Cmd.txt'))
        )
        if not command_file_matches:
            raise FileNotFoundError(
                f'No command file (*Command.txt or *Cmd.txt) found in {test_data_path}'
            )
        command_file_path = command_file_matches[0]

        # Run the application
        runApp(app_selection, command_file_path)
    else:
        raise ValueError(f'Invalid application selection: Must be one of: {", ".join(app_name_dict.keys())}')

    return
```
